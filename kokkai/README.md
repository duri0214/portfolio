# 国会会議録の読み仮名支援辞書

会議録の読み仮名支援辞書は、`kokkai` アプリの `ReadingSupportEntry` で管理します。辞書項目を削除すると、会議録の表示にも使われなくなります。

## KOKKAI内の管理画面

スーパーユーザーは、会議録一覧の「読み仮名支援辞書」から登録済み項目を確認・編集・削除できます。新しい項目の追加はCSV取り込みだけで行います。

## CSV形式

ファイルはUTF-8のカンマ区切りで、次の列を使用します。

```csv
word,reading,description,source_url
NISA,ニーサ,少額投資非課税制度,https://example.com/nisa
お諮り,おはかり,読み仮名を補正するための登録語です。,
```

`word`、`reading`、`description` は必須です。`reading` は会議録でJanomeの結果より優先して使い、`description` は読み仮名とともに表示します。`source_url` は任意で、値がある場合は出典リンクを表示します。用途を示す種別は持ちません。

画面の「CSVテンプレート（サンプル付き）をダウンロード」から、初期投入値と新規追加例を含むCSVを取得できます。

同じ正規化表記がCSV内に複数ある場合や、必須項目・URL形式が不正な場合は、CSV全体を保存しません。既存項目は同じ内容でもCSVの値で上書きし、重複レコードは作成しません。

## 操作確認用サンプルデータ

### 会派バーから観測区間への移動（Issue #975）

`issue_975_affiliation_periods.json` は、同じ日に会派Aと会派B、翌日に再び会派Aを観測した合成データです。一次資料のURLは実在する会議録ではなく、画面確認用の例です。既存データを変更せずに確認するには、次のコマンドでテストDBを使ったサーバーを起動します。

```powershell
.venv\Scripts\python.exe manage.py testserver kokkai/fixtures/issue_975_affiliation_periods.json --noinput
```

1. `http://127.0.0.1:8000/kokkai/traceability/?q=975` をブラウザで開きます。「検証用議員975」の行に3本のバーが表示されます。
2. バーを1本ずつクリックし、詳細画面の「会議録」欄が次の1件だけになっていることを確認します。戻るボタンで一覧へ戻り、次のバーを開きます。

   | クリックするバー | 詳細画面の会議録 |
   | --- | --- |
   | 会派A（2024-01-26） | `sample-975-01` |
   | 会派B（2024-01-26） | `sample-975-02` |
   | 会派A（2024-01-27） | `sample-975-03` |

3. 人物名「検証用議員975」をクリックすると、3区間すべてが表示されることを確認します。

`testserver` を終了しても `test_portfolio_db` は残ります。次に非対話でテストを実行する前に、`.codex/rules/django.md` に従ってこのテストDBを削除してください。

### 読み仮名支援辞書

画面の「CSVテンプレート（サンプル付き）をダウンロード」で取得できるCSVを、そのままアップロードして動作確認に使えます。マイグレーションで初期投入される`FOIP`と`お諮り`も同じ値で含まれているため、既存項目の上書きと`NISA`の新規追加を一度に確認できます。

1. スーパーユーザーで読み仮名支援辞書の「CSVから取り込む」を開き、「CSVテンプレート（サンプル付き）をダウンロード」で取得したCSVをアップロードします。新規1件、上書き2件になり、`お諮り`の出典が空欄になることを確認します。
2. 同じCSVをもう一度アップロードします。新規0件、上書き3件になり、重複レコードが作成されないことを確認します。
3. `FOIP`の行を `ＦＯＩＰ` に変更して再度アップロードし、全角・半角の違いでも既存項目が上書きされることを確認します。

## 表記の検出

辞書の検出では全角・半角、大小文字、空白を同一視します。登録済みの項目だけが会議録とシナリオゲームに反映され、表示時にLLMを使いません。
