# マージ後ブランチ整理

PRがマージされた後の作業環境を整理する。リモートブランチは残っている場合だけ一覧で提示し、削除するかどうかをユーザーに確認する。通常運用では削除を推奨する。

## 手順

1. `git status --short --branch` で現在ブランチと未コミット変更を確認する。
2. 未コミット変更がある場合は処理を中止し、変更を保持したまま状況を報告する。
3. `gh repo view --json defaultBranchRef --jq .defaultBranchRef.name` で既定ブランチを取得する。取得できない場合は、存在する `main` または `master` を使い、両方ある場合は確認を求める。
4. `git fetch origin <基準ブランチ> --prune` で基準ブランチとリモート追跡情報を更新する。
5. 切り替え前に現在ブランチ名を保持する。現在ブランチに対応するPRがある場合は、`gh pr view --json state,mergedAt,baseRefName,headRefName` でマージ済みであることを確認する。未マージのPRや確認できないブランチは削除しない。
6. 基準ブランチへ切り替える。現在ブランチが基準ブランチなら切り替えは不要。
7. `git branch --merged <基準ブランチ>` で候補を確認する。削除対象は、(a) 切り替え前のブランチにマージ済みPRがある場合のそのブランチ、または (b) ブランチ名が `<Issue番号>-...` / `issue/...` に該当し、`gh pr list --head <ブランチ名> --state merged` でマージ済みPRを確認できるブランチに限定する。基準ブランチ、保護対象、判定できないブランチは除外する。
8. 削除対象ごとに `git branch -d <ブランチ名>` を実行する。squash merge等で (a) のブランチだけが未マージ扱いになった場合は、対応PRの `headRefName` と一致し、PRがmergedであることを再確認したうえで、そのブランチに限り `git branch -D <ブランチ名>` を使用できる。未マージブランチには `-D` を使わない。
9. 削除したローカルブランチ名について、`git ls-remote --heads origin <ブランチ名>` でリモートに残っているか確認する。
10. リモートに残っているブランチがある場合は、対象ブランチを一覧で提示し、「通常運用どおり削除する」ことを推奨したうえで、ユーザーに削除可否を確認する。
11. ユーザーが削除を了承した場合だけ、対象ごとに `git push origin --delete <ブランチ名>` を実行する。了承されなかったブランチは残し、理由とともに報告する。
12. `git status --short --branch` と `git branch --list` で整理後の状態を確認する。

## 安全規則

- 未コミット変更がある状態で切り替えや削除を行わない。
- `main` と `master` は、同じコミットを指していても別名のブランチとして扱う。自動削除しない。
- 未マージブランチ、基準ブランチ、現在作業中のブランチは削除しない。
- リモートブランチを検出しただけでは削除しない。削除前に対象一覧を提示し、削除するかどうかを確認してユーザーの明示的な了承を得る。
- ユーザーが了承した場合だけ `git push origin --delete <ブランチ名>` を実行する。通常運用では削除を推奨する。
- `git branch -d` が失敗したブランチは、マージ済みPRのheadと一致する現在の作業ブランチ以外は強制削除せず、理由を報告する。
- Issueブランチ以外のローカルブランチを削除対象に含める場合は、ユーザーの明示的な指定が必要。

## 報告

次の項目を簡潔に報告する。

- 使用した基準ブランチ
- 削除したローカルブランチ
- 削除できなかったブランチと理由
- リモートに残っているブランチ
- リモート削除についてのユーザーの判断と実行結果
- 整理後の現在ブランチ
