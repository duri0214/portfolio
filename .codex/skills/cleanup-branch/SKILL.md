# マージ後ブランチ整理

PRがマージされた後の作業環境を整理する。リモートブランチは残っている場合だけ一覧で提示し、削除するかどうかをユーザーに確認する。通常運用では削除を推奨する。

## 手順

1. `git status --short --branch` で現在ブランチと未コミット変更を確認し、切り替え前のブランチ名を保持する。
2. 未コミット変更がある場合は、`git stash push -u -m "cleanup-branch:<元のブランチ名>"` で退避して処理を継続する。stashに失敗した場合は切り替えず、変更を保持したまま状況を報告する。
3. `gh repo view --json defaultBranchRef --jq .defaultBranchRef.name` で既定ブランチを取得する。取得できない場合は、存在する `main` または `master` を使い、両方ある場合は確認を求める。
4. `git fetch origin --prune` でリモートの全ブランチと追跡情報を更新する。基準ブランチだけを指定すると、削除済みの他ブランチに対応するローカル追跡refが残ることがあるため、fetch対象を限定しない。
   - fetch成功後、必要に応じて `git remote prune origin` を実行し、リモートに存在しない `origin/<branch>` の追跡refを削除する。これはローカルの追跡情報だけを変更するため、GitHub上のブランチ削除確認は不要とする。
   - fetchに失敗した場合は、リモートの実在ブランチを確定できないため、ブランチ削除や追跡refの手動削除を行わず、原因を報告する。
5. 切り替え前に現在ブランチ名を保持する。現在ブランチに対応するPRがある場合は、`gh pr view --json state,mergedAt,baseRefName,headRefName` でマージ済みであることを確認する。未マージのPRや確認できないブランチは削除しない。
6. 基準ブランチへ切り替える。現在ブランチが基準ブランチなら切り替えは不要。
7. 基準ブランチを最新化するため、`git pull --ff-only origin <基準ブランチ>` を実行する。fast-forwardできない、またはpullに失敗した場合は、差分と原因を報告してローカルブランチの削除を続けない。`git reset --hard` や強制更新でローカル変更を破棄しない。
8. `git branch --merged <基準ブランチ>` で候補を確認する。削除対象は、(a) 切り替え前のブランチにマージ済みPRがある場合のそのブランチ、または (b) ブランチ名が `<Issue番号>-...` / `issue/...` に該当し、`gh pr list --head <ブランチ名> --state merged` でマージ済みPRを確認できるブランチに限定する。基準ブランチ、保護対象、判定できないブランチは除外する。
9. 削除対象ごとに `git branch -d <ブランチ名>` を実行する。squash merge等で (a) のブランチだけが未マージ扱いになった場合は、対応PRの `headRefName` と一致し、PRがmergedであることを再確認したうえで、そのブランチに限り `git branch -D <ブランチ名>` を使用できる。未マージブランチには `-D` を使わない。
10. 削除したローカルブランチ名について、`git ls-remote --heads origin <ブランチ名>` でGitHub上に残っているか確認する。
11. リモートに残っているブランチがある場合は、対象ブランチを一覧で提示し、「通常運用どおり削除する」ことを推奨したうえで、ユーザーに削除可否を確認する。
12. ユーザーが削除を了承した場合だけ、対象ごとに `git push origin --delete <ブランチ名>` を実行する。了承されなかったブランチは残し、理由とともに報告する。
13. `git branch --remotes` でローカルのリモート追跡ブランチを確認する。`origin/HEAD -> origin/<基準ブランチ>` はシンボリックな既定ブランチ参照であり、実ブランチ数には含めない。実ブランチがGitHub上の一覧と一致しない場合は、fetch/prune結果を再確認し、未確定のまま手動削除しない。
14. stashを作成した場合は、元の作業ブランチへ戻してstashを復元するか、基準ブランチに残すかをユーザーに確認する。明示的な了承なしに基準ブランチへstashをpopしない。
15. `git status --short --branch`、`git branch --list`、`git branch --remotes` で整理後の状態を確認し、基準ブランチが `origin/<基準ブランチ>` と同期していることを確認する。

## 安全規則

- 未コミット変更はstashに退避してから切り替える。stashに失敗した場合は切り替えや削除を行わない。
- 基準ブランチの `git pull --ff-only` が失敗した場合は、ローカルブランチの削除を続けない。`reset --hard` や強制更新で差分を破棄しない。
- `main` と `master` は、同じコミットを指していても別名のブランチとして扱う。自動削除しない。
- 未マージブランチ、基準ブランチ、現在作業中のブランチは削除しない。
- リモートブランチを検出しただけでは削除しない。削除前に対象一覧を提示し、削除するかどうかを確認してユーザーの明示的な了承を得る。
- リモート追跡refのpruneと、GitHub上のリモートブランチ削除を区別する。前者はローカルの古い参照の掃除であり、後者だけがユーザー確認の対象になる。
- ユーザーが了承した場合だけ `git push origin --delete <ブランチ名>` を実行する。通常運用では削除を推奨する。
- `git branch -d` が失敗したブランチは、マージ済みPRのheadと一致する現在の作業ブランチ以外は強制削除せず、理由を報告する。
- Issueブランチ以外のローカルブランチを削除対象に含める場合は、ユーザーの明示的な指定が必要。

## 報告

次の項目を簡潔に報告する。

- 使用した基準ブランチ
- 基準ブランチのpull結果
- 削除したローカルブランチ
- 削除できなかったブランチと理由
- リモートに残っているブランチ
- リモート削除についてのユーザーの判断と実行結果
- stashの作成有無と復元についてのユーザーの判断・実行結果
- 整理後の現在ブランチ
