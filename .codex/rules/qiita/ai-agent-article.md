# 編集ルール（スタイルガイド） — AI Agent

適用対象: `docs/qiita/ai_agent.md`

## 目的

- Phase 1では、Qiita記事「（途中）AI Agent を試作する」の原本を内容を変えずにGitHubで管理する。
- Phase 2では、原本を出発点として、刷新後の `ai_agent/` の実装と記事の説明を対応付ける。

## 適用スコープ

- Qiita原本または刷新後のAI Agentの概要
- `ai_agent/` の実装、処理フロー、ツール、ガードレール、履歴管理の説明
- 記事から参照する関連Issue、コード例、検証手順
- 非対象: 記事の記述だけで実装済みと扱うこと、記事のテーマをルールで固定すること

## ルール

1) フェーズごとの扱いを分ける
   - Phase 1では、原本のタイトル、主題、説明順、表現を原則として変更しない。
   - Phase 2では、ターン制会話からSkill Chain型Agentへ、記事のタイトル、主題、構成、用語を変更してよい。

2) AI Agent固有の将来計画を明示する
   - OpenAI Moderation API・RAG・ベクトル検索は、実装されるまで将来の拡張として扱い、関連Issue #310 または #324を参照する。

3) 設計上の責務を実装に合わせる
   - Factory、Repository、Service、Value Object、Agent、Toolなどの責務は、対象フェーズの設計に合わせて説明する。
   - DDDの一般概念を残す場合も、刷新後のAgent、Tool、実行履歴などの責務に合わせて説明する。

4) リンクと履歴を維持する
   - 記事原本、`ai_agent/` のソース、親Issue、対象PhaseのIssueを参照できる状態にする。
   - #310、#324などの関連Issueは、刷新後も関係がある場合だけ残し、不要になったリンクは更新または削除する。

## チェックリスト（レビュー用）

- Phase 1ではQiita原本との差分が最小限になっているか。
- Phase 2では刷新後のAgentの目的・構成・処理を説明しているか。
- Agent、Tool、イベント、永続化の責務が実装と一致しているか。
- 関連Issueとソースコードへのリンクが、現在の設計と関係しているか。
- Phase 1で実装変更を混ぜていないか。
