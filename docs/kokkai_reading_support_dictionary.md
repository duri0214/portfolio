# 国会会議録の読み仮名支援辞書

会議録の読み仮名支援辞書は、`kokkai` アプリの `ReadingSupportEntry` で管理します。辞書項目を削除すると、会議録の表示にも使われなくなります。

## KOKKAI内の管理画面

スーパーユーザーは、会議録一覧の「読み仮名支援辞書」から登録済み項目を確認・編集・削除できます。新しい項目の追加はCSV取り込みだけで行います。

## CSV形式

ファイルはUTF-8のカンマ区切りで、次の列を使用します。

```csv
word,reading,description,source_url
NISA,ニーサ,少額投資非課税制度,https://example.com/nisa
お諮り,おはかり,,
```

`word`、`reading`、`description` は必須です。`reading` は会議録でJanomeの結果より優先して使い、`description` は読み仮名とともに表示します。`source_url` は任意で、値がある場合は出典リンクを表示します。用途を示す種別は持ちません。

同じ正規化表記がCSV内に複数ある場合や、必須項目・URL形式が不正な場合は、CSV全体を保存しません。既存項目は同じ内容でもCSVの値で上書きし、重複レコードは作成しません。

## 操作確認用サンプルCSV

[操作確認用サンプルCSV](kokkai_reading_support_dictionary_sample.csv)は、画面からそのままアップロードして動作確認に使えます。マイグレーション適用直後の開発用DBでは、`FOIP`と`お諮り`が既存項目の上書き、`NISA`が新規追加になります。

1. スーパーユーザーで読み仮名支援辞書の「CSVから取り込む」を開き、サンプルCSVをアップロードします。新規1件、上書き2件になり、`お諮り`の出典が空欄になることを確認します。
2. 同じCSVをもう一度アップロードします。新規0件、上書き3件になり、重複レコードが作成されないことを確認します。
3. `FOIP`の行を `ＦＯＩＰ` に変更して再度アップロードし、全角・半角の違いでも既存項目が上書きされることを確認します。

## 表記の検出

辞書の検出では全角・半角、大小文字、空白を同一視します。登録済みの項目だけが会議録とシナリオゲームに反映され、表示時にLLMを使いません。
