# 防犯カメラの録画をもう一度全部見るの？——Rustで動きのあった場面を探す「video-cue-engine」

## はじめに

昔、航空自衛隊にいた頃、たまに特別警備の応援に入ることがありました。そのときに気になったことがあります。

「防犯カメラの映像を確認するのに、録画と同じ時間をもう一度かけるのか？」

長い録画を初めから見直す前に、何かが動いた場面を先に探せたらどうだろう。そんな思いを形にしたのが、Rustで作った `video-cue-engine` です。定点カメラで録画したMP4を解析し、動きが検出された場面をつないだ確認用の動画を作ります。

解析結果は、必要に応じてDjangoで作った `VIDEO CUE` に送れます。Rustが録画を解析し、Djangoの画面でハイライトを再生したり、気になる場面を選んで見直したりする構成です。ローカルで解析するだけでも使えます。

この記事では、映像を確認する人が何に困り、どんな手がかりが欲しいのかを中心に、アプリの使い方と今できていることを紹介します。

## 欲しかったのは、見直す場所の手がかり

防犯カメラの映像には、変化の少ない時間もあれば、人や物が動く時間もあります。確認したい場面がいつ出てくるか分からなければ、映像を進めながら探すことになります。

そこで考えたのが、録画の中から「動きがあった」と検出された場面を集め、まずそこから見直す方法です。確認する人は、まとめられた映像で気になる場面を探し、詳しく調べたいときは元の録画に戻れます。

アプリが行うのは、見直す場所の候補を出すところまでです。何が起きたのか、確認が必要な場面なのかは、映像を見た人が判断します。

## 動いた場面を、一本の動画で見る

最初は、検出した動きごとに短い動画を作るところから始めました。ただ、場面がたくさんあると、その数だけファイルを開いて確認する必要があります。そこで、検出された区間を元の録画の順につないだ `highlights.mp4` を作るようにしました。[この変更の経緯はIssue #5](https://github.com/duri0214/video-cue-engine/issues/5)にも残しています。

各場面には動きの前後にも余白を付けています。前後が重なる場合は同じ映像を繰り返さずにつなぐため、続けて見たときに場面の流れを追いやすくなります。

ハイライトには、元の録画の先頭からの経過時間も表示します。たとえば `00:10:23.400` と表示されたら、元動画の開始から約10分23秒の場面です。時計の時刻ではありません。詳しく見たい場面があれば、この表示を手がかりに元動画の該当箇所へ戻れます。

![動きのある3つの場面と元動画の経過時間を表示するハイライト動画](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/94562/ae7bf85e-ede8-4a82-a73e-fa1f99f6fec6.gif)

*VIDEO CUEでサンプルのハイライトを再生し、元動画の経過時間を見ながら動きのある場面を続けて確認する。*

ハイライトは確認用に圧縮された、音声のない動画です。細部や音声を確認したい場合は元の録画を使います。検出した一つの動き区間を「イベント」と呼び、イベントごとの短いクリップと、時刻などを記録した `analysis.json` もローカルに保存します。動きが検出されなかった場合はJSONだけが作られ、ハイライトは作られません。

## フォルダーを選んでまとめて解析する

複数の録画を確認するときに、一つずつコマンドを入力するのは手間です。そこでWindows向けの画面を用意し、入力フォルダーと出力先を選んで一括解析できるようにしました。

画面で選択したフォルダーの直下にあるMP4が対象です。サブフォルダーの中までは探しません。開始前に対象の件数とファイル名を確認でき、解析中は動画ごとの進行状況や成功・失敗とその理由が表示されます。一つの動画が失敗しても、残りの動画の処理を続けます。

出力先の初期値はWindowsの「ダウンロード」フォルダーですが、別の既存フォルダーを選ぶこともできます。結果は実行ごとに別のフォルダーへ保存されるので、前回の結果を上書きせずに見比べられます。

![入力フォルダー、対象のMP4一覧、出力先を表示した一括解析画面](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/94562/a5a1dda4-1226-4f58-bca6-c3c302a00de2.png)

*対象の録画と保存先を確認してから解析を始める。*

画面を使わず、CLI（コマンドライン）で単一のMP4と出力先を指定して解析することもできます。自動化したい場合や、`--threshold` で動きを検出する変化量の基準を調整したい場合に使えます。

## ブラウザーで結果を見直す

複数の結果から気になる場面を選び直したいときのために、別途Djangoで `VIDEO CUE` という閲覧画面も用意しました。ローカルで解析した結果を受け取り、スタッフ権限でログインした人が、ブラウザーで録画の一覧とハイライトを見られます。

詳細画面では、動きが検出された区間の一覧やタイムラインを選び、その場面へ移動できます。「前」「次」でもイベントを切り替えられます。元動画内の時刻は動きの区間内で表示され、前後の余白では「区間外」と表示されます。

![ハイライト動画、元動画内の時刻、検出イベント一覧を表示したVIDEO CUE画面](https://qiita-image-store.s3.ap-northeast-1.amazonaws.com/0/94562/6ece3f0a-069c-48ef-b220-6a7f49bd12a3.png)

*サンプルのイベントを選び、気になる場面と元動画内の時刻を確認する。*

転送は任意で、GUIの「処理完了後に Django へ転送」は初期状態ではオフです。オンにした場合、解析に成功した動画のJSONと、動きがある場合のハイライトを送ります。元の長いMP4やイベントごとのクリップは送信しません。動きが検出されなかった場合はJSONだけを送ります。

送信に失敗してもローカルの成果物は残り、GUIの「ローカル成果物から再送」で解析し直さずに送れます。CLIでも `--upload` で送信、`--upload-existing` で保存済みの成果物を再送できます。ハイライトにも録画の映像が含まれるため、共有先や閲覧権限を確認して使います。Django側の受信設定と、エンジン側に同じトークンを設定したPowerShellからGUIを起動する準備が必要です。

## サンプルで使ってみる

Windowsで、Git、Rust / Cargo、FFmpegを用意します。`ffmpeg` と `ffprobe` をPATHから実行でき、FFmpegが `libx264` と `drawtext` に対応している必要があります。インストールやDjangoへの転送設定の詳細は、リポジトリのREADMEにまとめています。

以下は、ユーザーフォルダーに `video-cue-engine` フォルダーがまだない場合の例です。PowerShellで実行し、GUIをビルドして起動します。すでに取得済みの場合は、既存のリポジトリに移動して `cargo build` から実行してください。

```bash:console
cd $env:USERPROFILE
git clone https://github.com/duri0214/video-cue-engine.git
cd .\video-cue-engine
cargo build --release --features gui --bin video-cue-engine-gui
(Resolve-Path .\fixtures).Path
.\target\release\video-cue-engine-gui.exe
```

1. 「入力フォルダを選ぶ」で、PowerShellに表示された `fixtures` フォルダーを選び、`scene-motion.mp4` と `scene-still.mp4` の2件を確認します
2. 出力先を確認します。初期表示のフォルダーが使えない場合は「出力フォルダを変更」で書き込める既存のフォルダーを選びます
3. 転送はオフのまま「一括解析を開始」を押し、2件とも完了したら「今回の出力フォルダを開く」を押します
4. `scene-motion.mp4` の結果フォルダー `0001` で `highlights.mp4` を再生し、人の通過、ドアの開閉、箱の移動を模した3つの場面と、映像内の元動画の経過時間を確認します
5. `scene-still.mp4` の結果フォルダー `0002` には `analysis.json` があり、ハイライト動画はないことを確認します

このサンプルは、動きの時刻が分かるように作られた短い映像です。ビルド済みGUIでローカル解析だけを行う場合は、利用するPCにRustやDjangoは不要ですが、FFmpegとffprobeは必要です。

## 使う前に知っておきたい限界

動きの検出は、動画から取り出した画像同士の変化を比べて行います。Rustが変化量から区間をまとめ、FFmpegが映像の読み込みや動画の書き出しを担当します。人物、車両、顔、行動の種類や、事件かどうかを判別する機能はありません。

照明の変化やカメラの揺れを動きとして検出することもあれば、小さい動きや短い動きを見逃すこともあります。「検出0件」は、何も起きなかったことの証明ではありません。実際の録画に合わせた確認や、CLIのしきい値の調整が必要です。

解析には録画を読み取る時間と動画を書き出す時間がかかります。また、動きが多い録画ではハイライトも長くなります。実際の防犯カメラ映像での精度や処理時間は、これから確認していきたいところです。常に確認作業が短くなると保証できるものではありません。現在の対象は録画済みMP4で、リアルタイムのカメラ接続には対応していません。

警備の応援に入っていた頃に感じた、「長い録画の確認には、もう一度同じだけ時間がかかるのか」という疑問。そこから、まずは確認する場所の手がかりを作る道具として形にしました。実際の録画でも使いやすいかを確かめながら、見直す人の負担を減らせるように育てていきたいと思います。
