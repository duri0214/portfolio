# DJをしながら映像も届けたい——Rustで作ったVJ支援アプリ「vj-copilot」

## はじめに

DJをしながら、曲に合った映像も自分で出したい。

`vj-copilot` は、そんな思いから作ったWindows向けのアプリです。流れている音をもとに映像の候補を出し、その中からDJ自身が選んで画面に映します。さらに、背景映像の上に透過画像を重ねて、好きなタイミングで演出を加えることもできます。

作ったきっかけは、ずっと前に自分がDJをしていた頃の経験でした。当時、使う側として欲しかったものを、今になってRustとeguiで形にしています。

> **静止画プレースホルダー1**
>
> - 撮影対象: 操作画面と、隣に開いた映像表示ウィンドウを含むPC画面全体
> - 画面の状態: デモを起動し、背景動画を選択して映像表示ウィンドウに表示している状態
> - 伝えたいこと: DJが候補を選び、別ウィンドウで映像を届ける構成
> - 代替テキスト: 「映像候補を並べた操作画面と、選択した映像を表示するウィンドウ」
> - キャプション: 「音に合わせた候補から映像を選び、別ウィンドウに表示する」

## ニコ生でDJをしていた頃、欲しかったもの

2008年末ごろ、ニコニコ生放送でDJをするコミュニティは、私の周りではまだごく少ないものでした。自分のコミュニティは、DJを掲げたものとして2つ目くらいだったと記憶しています。

初音ミクをはじめとするボーカロイドの音楽も、今ほど幅広い場所で当たり前に耳にする前の時代でした。私は `duri（ドリ）` としてニコ生でDJをし、2011年頃にも活動していました。ボーカロイドの楽曲をリミックスしたり、自分で映像を作ったりもしていました。

当時の活動に関するページは、[ニコニコ大百科の「DJ生主 ドリ」](https://dic.nicovideo.jp/l/dj%E7%94%9F%E4%B8%BB%20%E3%83%89%E3%83%AA)と[ピアプロのプロフィール](https://piapro.jp/duri)です。ピアプロには、DJ放送「ミッフィーおとあそび」と作品の記録を載せています。なお、当時のニコニコミュニティは、[2024年にサービスの再開が断念](https://group.kadokawa.co.jp/information/media-download/1366/c6cbfa26fb96e9b6/)されています。

その頃、私の知っていた現場では、音と映像の分業が当たり前でした。DJは音をつなぎ、VJは映像を担当していました。でも、DJをしている自分でも、曲の雰囲気に合う映像を一緒に届けられたら面白い。そう思っていました。

とはいえ、曲を選び、次の曲につなぎながら、別の画面で大量の映像素材を探して出すタイミングまで考えるのは大変です。欲しかったのは、映像の操作を全部自分の代わりに決める仕組みではなく、DJを続けながら映像も選べるように手を貸してくれる道具でした。

## DJの頭出しのように、STAGINGで確認する

DJが次の曲をヘッドホンで頭出しするように、前景画像は操作画面の `STAGING` で位置や動きを確かめられます。`PLAY` を押すと、確認した前景が `STAGE` に表示されます。

`STAGE` は、選んだ背景と前景を映す、操作画面とは別のプレビューウィンドウです。映像全体の見え方を確認したり、サブディスプレイやプロジェクターへ移して観客に見せたりできます。背景動画は候補欄の動くプレビューで確認し、選んだ時点でSTAGEに表示されます。

## 音をつなぎながら、映像も選ぶ

音を聴きながら、アプリが次に使う背景映像を最大4本提案します。候補は動くので、映像の雰囲気を見比べられます。「これを出したい」と思ったものをDJが選ぶと、別ウィンドウの `STAGE` に映ります。

選んだ後、候補の自動更新は保留されます。DJの操作中に候補が入れ替わって、選ぼうとしていた映像を見失わないようにするためです。選択を解除すれば、また音に合わせた候補が表示されます。

映像はアプリが勝手に切り替えるのではなく、自分で決めます。音と映像を一人で扱うために、探す作業を助けてもらい、最後の選択はDJが行う。そこがこのアプリのいちばん大事なところです。

> **GIFプレースホルダー2**
>
> - 撮影方法: Windows 11ならSnipping Toolなどで画面を録画し、GIFに変換する
> - 録画対象: 操作画面の音量・BPM表示とBackground候補の領域
> - 画面の状態・操作: デモで候補が動き、更新される様子を映してから、1本を選び、選択後もしばらく録る
> - 伝えたいこと: 動く候補を比べてDJが選び、その間は候補の自動更新を保留すること
> - 代替テキスト: 「背景映像の候補を見比べ、1本を選択する操作画面」
> - キャプション: 「動く候補を見比べて選ぶと、その間の自動更新を保留する」

## 背景に、好きな前景を重ねる

背景動画とは別に、透過PNGを `Foreground` として重ねられます。たとえば、曲にちなんだ画像やシルエットを用意しておき、ここぞというタイミングで背景の上に出す使い方を想定しています。

Foregroundを選ぶと、まず操作画面の `STAGING` に表示されます。ドラッグで位置を調整し、`Y SPIN ON/OFF` で回転風の動きを切り替えても、その時点ではSTAGEの表示は変わりません。`PLAY` を押して初めて、確認した位置と動きがSTAGEに反映されます。

別のForegroundを準備している間も、いまSTAGEに出している画像は残ります。次の画像を選び直して配置してから `PLAY` を押せば、そこで切り替わります。プレビューを開いていない出力中は `STOP` で前景を消せます。前景タブやSTAGEウィンドウで `Space` を押した場合も、背景を維持したまま前景のプレビューと出力を解除できます。

> **GIFプレースホルダー3**
>
> - 撮影方法: Windows 11ならSnipping Toolなどで画面を録画し、GIFに変換する
> - 録画対象: ForegroundタブのSTAGINGとSTAGEウィンドウ
> - 画面の状態・操作: 左側のサンプルをSTAGEに表示したまま、右側のサンプルをSTAGINGで選んでドラッグし、`PLAY` を押す
> - 伝えたいこと: 位置を調整している間は出力中の画像を維持し、`PLAY` で次の画像に切り替わること
> - 代替テキスト: 「出力中の前景を残して次の画像を配置し、PLAYで切り替える操作」
> - キャプション: 「次の前景を確認・配置してからSTAGEへ出す」

> **静止画プレースホルダー4**
>
> - 撮影対象: STAGEウィンドウとForegroundの操作欄
> - 画面の状態: GIF3のSTAGINGから `PLAY` を押し、右側のサンプルを背景に重ねて `STOP` を表示した状態
> - 伝えたいこと: 確定操作で前景を切り替え、停止操作で消せること
> - 代替テキスト: 「背景動画に前景画像を重ねたSTAGEとSTOPボタン」
> - キャプション: 「PLAYで配置をSTAGEへ反映し、STOPで前景を消す」

## どうやって候補を出しているか

入力は、WindowsのPC再生音、LINE / MIC、またはデモ用の合成音です。アプリは音の大きさと周波数の傾向から、音の `energy` と `brightness`という2つの値を求めます。

背景動画にも、あらかじめ同じ名前の2つの値を付けておきます。アプリは音と動画の値の距離を比べ、近い素材を候補に選びます。候補は約2秒間隔で更新し、引き続き候補に残る映像は、なるべく同じ枠に置きます。

音の明るさと映像の明るさが合えば気持ちよく感じるかもしれない、という仮説から始めた仕組みです。曲名や歌詞を認識して映像を探しているわけではありません。画面には音量メーターと実験的なBPM・拍の推定も表示しますが、BPMは候補選びや映像の拍同期には使っていません。

## デモを試す

### 準備するもの

WindowsでGit、Rust stableのMSVCツールチェーン、FFmpegを使います。以降のコマンドはPowerShellで実行してください。

Rustがない場合は、[Rust公式のインストール案内](https://www.rust-lang.org/tools/install)から `rustup-init.exe` を入手し、表示される案内に従います。Rustと一緒に `cargo` が入り、必要に応じてC++ビルドツールも準備します。

FFmpegがない場合は、例えば次のコマンドで導入できます。サンプル動画の生成には `libx264` 対応のFFmpegが必要です。

```bash:console
winget install "FFmpeg (Essentials Build)"
```

`winget` を使えない場合のダウンロードやPATHの設定は、別アプリ `cutup-studio` のFFmpeg導入手順にまとめています。そこではFFmpegの項を参照してください。

https://github.com/duri0214/cutup-studio/blob/main/src/infra/local_ai/README.md

導入後は新しいPowerShellを開き、次のコマンドでそれぞれのバージョンが表示されることを確認します。

```bash:console
git --version
rustc --version
cargo --version
ffmpeg -version
```

### 起動する

次は、Windowsのユーザーフォルダーに `vj-copilot` フォルダーがまだない場合の例です。最初にユーザーフォルダーへ移動し、取得したリポジトリへ移動してから、素材の生成とデモの起動を行います。

```bash:console
cd $env:USERPROFILE
git clone https://github.com/duri0214/vj-copilot.git
cd .\vj-copilot
.\scripts\generate-background-metadata.ps1
cargo run --release -- --demo
```

すでに取得済みの場合は、既存の `vj-copilot` フォルダーへ移動して、素材生成から実行してください。生成スクリプトは `demo-media/background` の同名サンプルMP4と `background-metadata.json` を上書きします。自分の素材や編集済みメタデータがある場所では実行しないでください。

デモは入力機器なしで動きます。音の特徴が約5秒ごとに変化する合成PCMを解析に使うので、候補の更新を試せます。合成音がスピーカーから流れるわけではありません。

1. 操作画面のBackgroundタブで、動く映像候補を見比べます
2. 候補をクリックするか `1`〜`4` キーで選び、STAGEへの表示と候補の保留を確認します
3. Backgroundタブで `Space` を押し、選択を解除して自動更新に戻します
4. Foregroundタブで同梱の `neon-orbit-left.png` や `neon-prism-right.png` を選び、STAGINGで位置を決めて `PLAY` を押します

実際の音を使うときは `cargo run --release` で起動し、`PC 再生音` または `LINE / MIC` とデバイスを選んで `開始` を押します。PC再生音の場合は、音楽を再生しているWindowsの出力先と同じデバイスを選びます。

自分の素材を使う場合は、`demo-media/background` にMP4と `background-metadata.json` を置き、`demo-media/foreground` に透過PNGを置いてから起動します。背景のメタデータには、素材ごとに `energy` と `brightness` を0〜1で指定します。

素材の置き方、通常起動、ASIO対応版、エラー時の確認方法はREADMEにまとめています。ソースコードもこちらからたどれます。

https://github.com/duri0214/vj-copilot/blob/main/README.md

## 試作としてできていること、これから試したいこと

いまの背景動画は、読み込み時に先頭最大3秒を320×180、15 fpsのフレームに変換してループ表示します。動画全体を再生する機能や、動画の音声を出す機能はありません。前景として同時に表示できるPNGは1枚で、位置と回転の設定はアプリの起動中だけ保持します。STAGEは別ウィンドウとしてサブディスプレイへ移動できますが、専用の映像出力プロトコルには対応していません。

初めは音に合わせた背景候補を選ぶところから作り、そこに前景の重ね合わせ、STAGEの分離、出す前のSTAGINGを少しずつ加えました。候補を保留することも、前景を確認してから出すことも、DJの手を止めず、意図しない映像を出さずに使いたいという考えにつながっています。

まだ試作なので、実際の音楽とDJ操作を並行した候補選択の評価はこれからです。音の特徴と映像の相性や、限られた操作で選びやすいかも、実際に使いながら確かめたいと思っています。LLM / VLMを使った素材検索などは初期の検討に挙がった拡張案であり、現在の機能ではありません。

ニコ生でDJをしていた頃、一人でも音に映像を添えられたらと思っていました。あの頃の自分が使いたかった道具に、少しずつ近づけていきたいです。
